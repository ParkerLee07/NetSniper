# NetSniper v2.1 Deterministic Corpus Activation

Status: development and regression corpus checkpoint.

## Activated fixtures

This checkpoint activates exactly:

- 14 development fixtures;
- 4 regression fixtures; and
- 0 evaluation fixtures.

All 12 evaluation fixtures remain planned. The evaluation assignments and
expectations remain frozen at the first v2.1 classifier implementation commit
and are not used to tune this checkpoint.

Each active fixture has:

- one tracked synthetic source artifact;
- one tracked normalized replay input;
- a recorded ground-truth timestamp;
- family, role, platform, identity, uncertainty, and legacy expectations; and
- a stable development or regression split assignment.


## Anti-leakage boundary

Active classification fixtures may contain only evidence that the production
normalization and collection paths can represent. They must not inject
`network_role`, `network_roles`, `role`, or `roles` fields containing the
classification target.

The access-point, managed-switch, and router fixtures therefore rely on
observable vendor, hostname, service-product, port, and OS evidence rather than
pre-labeled roles. The corpus validator rejects future target-label leakage.

## Deterministic replay

Run the active corpus directly:

```bash
./tools/replay_v2_1_corpus.py \
  --split development \
  --split regression \
  --summary-only
```

The replay uses a fixed timestamp and executes every input twice. Canonical JSON
results must be byte-identical. The validator also requires full host retention,
contract validity, uncertainty-reason compliance, confidence-cap compliance,
strong-contradiction review, legacy-projection agreement, and fixture expectation
agreement.
