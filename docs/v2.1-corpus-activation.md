# NetSniper v2.1 Deterministic Corpus Activation

Status: conventional development and regression test checkpoint.

## Active cases

The corpus contains exactly:

- 14 development fixtures; and
- 4 regression fixtures.

All 18 are ordinary deterministic test cases. The former formal evaluation
split, prepared holdout inputs, candidate seals, replay authorization, and
statistical-claim controls are not part of the v2.1 release process.

Each active fixture has:

- one tracked synthetic source artifact;
- one tracked normalized replay input;
- a fixed provenance timestamp;
- family, role, platform, identity, uncertainty, and legacy expectations; and
- a development or regression assignment.

## Anti-leakage boundary

Classification fixtures may contain only evidence that the production
normalization and collection paths can represent. They must not inject
`network_role`, `network_roles`, `role`, or `roles` fields containing the
classification target.

The access-point, managed-switch, and router cases therefore rely on observable
vendor, hostname, service-product, port, and OS evidence rather than pre-labeled
roles.

## Deterministic replay

Run the complete corpus directly:

```bash
./tools/replay_v2_1_corpus.py \
  --split development \
  --split regression \
  --summary-only
```

The replay uses a fixed timestamp and classifies every input twice. Canonical
JSON results must be byte-identical.

## Exact gates

The 18 active fixtures must maintain:

- deterministic replay rate: 100%;
- host retention rate: 100%;
- schema validity rate: 100%;
- uncertainty-reason compliance: 100%;
- confidence-cap compliance: 100%;
- contradiction review rate: 100%;
- legacy-projection match rate: 100%;
- fixture expectation pass rate: 100%;
- false high-confidence classifications: 0; and
- false classified unknown controls: 0.

Run:

```bash
./tools/validate_v2_1_corpus_activation.py
```

These are regression-test requirements, not statistical accuracy claims.
