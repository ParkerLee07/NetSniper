# NetSniper v2.1 Observation and Risk Integrity

## Purpose

Nmap GNMAP and XML artifacts can describe the same open service. The v2.1
analysis path previously appended both records, which duplicated findings and
risk points. This checkpoint makes the analysis boundary canonical before
classification and risk calculation.

## Canonical port identity

A service observation is unique by:

- protocol;
- port number; and
- state.

When duplicate records share that identity, NetSniper emits one observation and
retains the richest available metadata for each field. XML product, version,
extra information, device type, and service fingerprint values therefore enrich
rather than duplicate the GNMAP observation.

## Finding and risk identity

A finding is scored once per finding ID, protocol, and port. Closed or otherwise
non-open records do not create findings. `analysis.json`, `analysis.txt`, and the
copy preserved in `analysis.enriched.json` must agree on finding count, score,
and severity.

## Privacy boundary

The regression fixture uses the documentation-only `192.0.2.0/24` address range
and synthetic product strings. It contains no captured IP address, MAC address,
hostname, domain, banner, or service fingerprint from the reference network.

## Scope boundary

This checkpoint does not change:

- classification taxonomy;
- evidence profiles or confidence thresholds;
- classifier or legacy-projection logic; or
- deterministic corpus expectations.
