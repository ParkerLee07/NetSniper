# NetSniper v2.1 Embedded Administration Boundary

## Purpose

Many printers, cameras, controllers, routers, storage appliances, and other
embedded systems expose HTTP or HTTPS administration pages. A web-facing
management plane is not the same operational role as a standalone web server.
This checkpoint prevents web-service metadata from overstating that role.

## Evidence independence

Port presence, HTTP titles, and HTTP service-product strings all originate from
the same web-service observation domain. They may strengthen a candidate but do
not count as independent corroboration. A classified `web_server` role requires
both:

- recognizable web-runtime evidence; and
- independent server context, such as a server-capable OS fingerprint or a
  distinct non-HTTP server service.

A server-oriented hostname is context only and cannot independently cross the
classified threshold.

## Embedded administration guard

Machine-readable guard policy lives in
`classification/evidence_profiles.json`. Management markers and corroborating
appliance family or role evidence cap `web_server` below the possible threshold
and attach `embedded_admin_interface`. The actual appliance role remains
available for classification and legacy projection.

This guard does not suppress legitimate web applications or standalone servers;
it prevents their management transport from being confused with the device's
primary operational role.
