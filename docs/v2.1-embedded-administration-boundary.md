# NetSniper v2.1 Embedded Administration Boundary

## Purpose

HTTP and HTTPS ports are common on routers, printers, cameras, controllers, and
other appliances because those devices expose administration interfaces. Web
transport alone must not cause an appliance to be classified as a standalone
web server.

## Evidence independence

HTTP port presence, HTTP titles, and HTTP product strings share the
`web_service` independence group. Repeated evidence from that same channel does
not count as independent corroboration.

A classified `web_server` role requires both:

- web-runtime evidence; and
- independent server context, such as a server-capable OS fingerprint or a
  distinct non-HTTP server service.

A server-oriented hostname is context only and cannot independently cross the
classified threshold.

## Embedded administration guard

Machine-readable guard policy lives in
`classification/evidence_profiles.json`. Management markers and corroborating
appliance family or role evidence cap `web_server` below the possible threshold
and attach `embedded_admin_interface`. The actual appliance role remains
available for classification and legacy projection.

This guard does not suppress legitimate web applications or standalone servers;
it prevents their management transport from being confused with the device's
primary operational role.

## Privacy and regression boundary

Regression cases use documentation-only addresses and synthetic product text.
No captured address, MAC, hostname, banner, domain, or fingerprint is committed.
The seven embedded-administration cases run as ordinary deterministic regression
checks in the complete v2.1 gate.

Run:

```bash
./tools/validate_v2_1_embedded_admin_boundary.py
```
