## Purpose

This checkpoint prepares the evaluation holdout without executing it. The
classifier candidate, frozen expectations, and prepared synthetic inputs are
fingerprinted in `fixtures/device-corpus/evaluation/seal.json` before the first
evaluation replay.

The evaluation split remains a process holdout. Repository visibility is not a
blind-test guarantee, so contributors must not tune classifier rules, weights,
thresholds, or expectations after evaluation outcomes are viewed.

## No-result preparation gate

Run:

```bash
./tools/validate_v2_1_evaluation_preparation.py
```

This validator performs structural, confinement, anti-leakage, fingerprint,
holdout, and no-results checks. It deliberately does not classify or replay any
evaluation fixture.

The existing development and regression corpus remains the only replayed set at
this checkpoint.

## First evaluation replay

The first evaluation replay remains blocked until all three sanitized-real
fixtures have genuine source evidence, normalized evidence, independent ground
truth provenance, and recorded timestamps.

Before that replay:

1. verify the seal against the candidate runtime;
2. activate all 12 evaluation fixtures in one reviewed checkpoint;
3. record a new complete input index including the sanitized-real captures;
4. execute the evaluation once against the sealed candidate;
5. store the immutable result report without changing the candidate; and
6. treat failures as release blockers rather than tuning feedback.

The 12-case starter evaluation set is too small for statistical accuracy claims.
It may support only corpus, regression, compatibility, and safety-gate claims.
