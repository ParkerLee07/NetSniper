# NetSniper v2.1 Accuracy Corpus

This directory defines the manually approved Stage 0C corpus contract.

## Files

- `schema.json` defines the machine-readable corpus manifest contract.
- `manifest.json` records planned, active, and retired labeled fixtures.
- Active development/regression evidence is stored beneath `fixtures/device-corpus/active/`.
- Sealed but not yet executed evaluation inputs are stored beneath `fixtures/device-corpus/evaluation/prepared/`.

## Corpus principles

1. Ground truth is recorded before classifier output is evaluated.
2. Device family, roles, platform, identity stability, and observation quality
   are labeled separately.
3. Synthetic fixtures are deterministic regression tests.
4. Sanitized real-world fixtures are required before accuracy claims are made.
5. Missing collectors and partial scans are not treated as negative evidence.
6. A service role may be classified while device family remains unknown.
7. Unknown and review outcomes are valid expected results.
8. Legacy compatibility projections are tested explicitly.
9. A fixture marked `active` must reference at least one source artifact and one
   normalized-evidence file.
10. Planned fixtures do not count toward Stage 0D accuracy thresholds.
11. A planned evaluation fixture may reference sealed preparation artifacts without becoming replayable or counting toward release gates.

## Manual activation workflow

For each planned fixture:

1. Create or sanitize the source evidence.
2. Record how ground truth was established.
3. Store development/regression normalized evidence under `fixtures/device-corpus/active/`; store held-out evaluation preparation inputs under `fixtures/device-corpus/evaluation/prepared/`.
4. Add the source-artifact paths to the manifest.
5. Set `recorded_at`.
6. Change the fixture status from `planned` to `active`.
7. Validate the manifest against `schema.json`.
8. Review the expected confidence ceiling and uncertainty reasons.
9. Do not tune the classifier using a fixture that is reserved as an evaluation
   fixture.

## Dataset split

Before v2.1 classifier calibration begins, active fixtures must be divided into:

- `development`: visible during rule design.
- `evaluation`: held out until calibration review.
- `regression`: permanently retained after a defect is fixed.

The split field will be added during Stage 0D together with measurable accuracy
and calibration thresholds.
