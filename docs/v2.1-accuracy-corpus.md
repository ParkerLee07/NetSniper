# NetSniper v2.1 Deterministic Test Corpus

The device corpus is a conventional saved-input test suite for the v2.1
classifier. It does not define new runtime device categories and it is not a
formal benchmark.

## Files

- `schema.json` defines the machine-readable manifest contract.
- `manifest.json` records the 18 active development and regression cases.
- Source and normalized replay inputs are stored beneath
  `fixtures/device-corpus/active/`.

There is no evaluation split, holdout seal, result directory, or replay
authorization state.

## Corpus principles

1. Device family, roles, platform, identity stability, and observation quality
   are tested separately.
2. Synthetic inputs are deterministic software tests.
3. Missing collectors and partial scans are not treated as negative evidence.
4. A service role may be classified while device family remains unknown.
5. Unknown and review outcomes are valid expected results.
6. Legacy compatibility projections are tested explicitly.
7. Every active case references one source artifact and one normalized replay
   input.
8. Test inputs must not inject their expected classification as observable
   evidence.
9. Test pass rates are not real-world accuracy percentages.
10. Raw real-network captures are never committed to this corpus.

## Adding or changing a case

A new case should be added only to represent a useful development scenario or
to protect a specific regression. The change must include:

1. a deterministic source record;
2. normalized evidence that production paths can represent;
3. explicit ground truth and expectations;
4. a development or regression split assignment;
5. anti-leakage review; and
6. successful replay through the complete v2.1 gate.

Changes to classifier behavior, taxonomy, or evidence policy remain separate
scope decisions and are not implied by editing a test case.
